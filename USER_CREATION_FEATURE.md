# User Creation Feature - Implementation Guide

## Overview
Added a complete user creation feature that allows administrators to create new user accounts with custom email, name, and roles (Admin, Lecturer, Student). The implementation uses Firebase Cloud Functions for secure server-side user creation.

## What Was Implemented

### 1. Cloud Function for User Creation
**File**: `functions/index.js`

Added `createUser` Cloud Function that:
- ✅ Validates admin permissions (only admins can create users)
- ✅ Creates Firebase Authentication user with email and password
- ✅ Creates Firestore document with user data and roles
- ✅ Returns success/error response to the app
- ✅ Includes proper error handling and security checks

### 2. Android App Updates

#### AdminViewModel.kt
- Added `UserCreateState` sealed class for managing creation state
- Added `createUser()` function that calls the Cloud Function
- Added `resetCreateState()` function for state management
- Integrated Firebase Functions SDK

#### UserManagementScreen.kt
- Added Floating Action Button (FAB) with "+" icon
- Added `CreateUserDialog` composable with form fields:
  - Name (required)
  - Email (required, validated)
  - Password (required, minimum 6 characters)
  - Role checkboxes (Student, Lecturer, Admin)
- Added form validation with error messages
- Added success/error snackbar notifications
- Added loading state during creation

#### Dependencies
- Added `firebase-functions-ktx` to `libs.versions.toml`
- Added implementation in `app/build.gradle.kts`

## Features

### User Creation Dialog
The dialog includes:
- **Name field**: Required text field for user's full name
- **Email field**: Required, validates email format
- **Password field**: Required, minimum 6 characters, masked input
- **Role checkboxes**: 
  - Student (checked by default)
  - Lecturer
  - Admin
- **Validation**: Real-time error messages for invalid inputs
- **Loading indicator**: Shows progress during creation
- **Disabled controls**: Prevents multiple submissions while loading

### Security
- Only authenticated admins can create users (verified server-side)
- Cloud Function checks admin role in Firestore before allowing creation
- Password is securely handled by Firebase Authentication
- HTTPS-only callable function

### User Experience
- Floating Action Button for easy access
- Form validation prevents invalid submissions
- Success snackbar confirms user creation
- Error snackbar shows detailed error messages
- User list automatically refreshes after creation
- Dialog can be dismissed by tapping outside or Cancel button

## How to Use

### As an Admin:

1. **Navigate to User Management**
   - Open hamburger menu
   - Tap "User Management"

2. **Create a New User**
   - Tap the floating "+" button (bottom-right)
   - Fill in the form:
     - Enter user's full name
     - Enter email address
     - Enter password (minimum 6 characters)
     - Select roles (one or more)
   - Tap "Create User"
   - Wait for success message
   - New user appears in the list

3. **User Can Now Login**
   - The created user can now log in with their email and password
   - They will have the roles assigned by the admin

## Firestore Document Structure

When a user is created, the following document is created:

```
users/
  {uid}/  (generated by Firebase Auth)
    email: "user@example.com"
    name: "John Doe"
    createdAt: Timestamp
    roles: {
      student: true,
      lecturer: false,
      admin: false
    }
```

## Error Handling

### Common Errors and Solutions:

1. **"Email already exists"**
   - Solution: Use a different email address

2. **"Only administrators can create users"**
   - Solution: Ensure current user has admin role set to true

3. **"Password should be at least 6 characters"**
   - Solution: Use a longer password

4. **"User must be authenticated to create users"**
   - Solution: Ensure you're logged in

5. **"Failed to create user"**
   - Solution: Check Firebase Functions logs in console

### View Function Logs:
```bash
firebase functions:log
```

Or in Firebase Console:
- Go to Functions
- Click on `createUser`
- View Logs tab

## Security Considerations

### ✅ Implemented:
- Server-side admin verification
- HTTPS-only callable function
- Password handled by Firebase Auth (not stored in Firestore)
- Authentication required

### ⚠️ Production Recommendations:
1. **Rate Limiting**: Add rate limiting to prevent abuse
2. **Email Validation**: Add more robust email validation
3. **Password Policy**: Implement stronger password requirements
4. **Audit Logging**: Log all user creation events
5. **Email Verification**: Send verification emails to new users
6. **Firestore Rules**: Add rules to prevent direct document creation

### Example Firestore Security Rules:
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      // Only allow reads by the user themselves or admins
      allow read: if request.auth != null && (
        request.auth.uid == userId ||
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.roles.admin == true
      );
      
      // Only admins can update roles (done via Cloud Function)
      allow write: if false; // All writes must go through Cloud Functions
    }
  }
}
```

## Troubleshooting

### Function Not Found Error
**Problem**: "Firebase function 'createUser' not found"

**Solutions**:
1. Deploy the function: `firebase deploy --only functions`
2. Check Firebase Console → Functions
3. Verify function name matches exactly: "createUser"
4. Check logs: `firebase functions:log`

### Permission Denied Error
**Problem**: "Only administrators can create users"

**Solutions**:
1. Verify admin user has `roles.admin: true` in Firestore
2. Check you're logged in as admin
3. Refresh user data (logout and login again)

### Build Errors
**Problem**: Cannot resolve firebase-functions

**Solutions**:
1. Sync Gradle: File → Sync Project with Gradle Files
2. Clean build: `./gradlew clean build`
3. Invalidate caches: File → Invalidate Caches / Restart
